# PDF Ukrainian — учебный desktop-проект

Мини-приложение на **Python + PyQt6**, которое извлекает текст из PDF,
переводит его на украинский через **MyMemory или Google Translate / deep-translator**
и сохраняет новый PDF. Сервер, Docker и API-ключи не нужны, нужен интернет.
**PyInstaller** упаковывает приложение вместе с Python и Qt.
**Jenkins** запускает тесты, собирает приложение и сохраняет ZIP-артефакт.

## Быстрый старт

Нужен Python **3.10–3.13**. Проверено здесь на Python 3.13 и macOS ARM64.
В macOS системный `python3` может быть старее: в таком случае используйте
`python3.13` вместо `python3` в первой команде.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python main.py
```

Windows PowerShell: вместо `source` выполните `.venv\Scripts\Activate.ps1`.
Без активации можно вызывать `.venv\Scripts\python.exe` напрямую.
`requirements.txt` содержит только зависимости приложения; lock-файл также
включает инструменты тестирования и сборки с зафиксированными версиями.

Небольшой английский PDF для ручной проверки: [translation-test-en.pdf](samples/translation-test-en.pdf).
Это одна страница с выделяемым текстом, OCR не требуется.

## Как устроен перевод

В окне выбирается переводчик. Автоматического переключения между сервисами
нет: текст отправляется только выбранному провайдеру.

По умолчанию выбран **MyMemory**: настоящий перевод короткого PDF на украинский
проверен в этой среде. Сервер и ключ не нужны; язык оригинала выбирается
вручную (английский или русский). Бесплатный лимит без ключа — **5000 символов
в день**. Остаток лимита зависит от предыдущих запросов с того же IP.
Документы длиннее 5000 символов отклоняются до отправки текста.
Это вариант для маленьких учебных PDF, а не для книг.
[Лимиты MyMemory](https://mymemory.translated.net/doc/usagelimits.php).

**Google Translate** тоже доступен, с автоопределением языка. При проверке
31 октября 2026 года Google вернул HTTP 429 даже на первом коротком запросе.
Этот внешний отказ нельзя исправить изменением PDF или упаковки PyInstaller.
При таком ответе выберите MyMemory и явно укажите язык оригинала.

Минимальный пример Google Translate через `deep-translator`:

```python
from deep_translator import GoogleTranslator

text = GoogleTranslator(source="auto", target="uk").translate("Hello world!")
```

В приложении текст для Google делится на части до 1800 символов, для
MyMemory — до 500 байтов UTF-8 (кириллические буквы занимают больше одного
байта). Переводятся все страницы, а не только первая.

Это не официальный Google Cloud Translation API: Google может временно
ограничить запросы, а изменения веб-страницы могут потребовать обновления
библиотеки. Приложение показывает понятную ошибку и сохраняет прежний файл
результата, если перевод не завершился.

Документация: [deep-translator](https://deep-translator.readthedocs.io/en/latest/usage.html).

## Как пользоваться

1. Выберите PDF, в котором можно выделить текст.
2. Оставьте MyMemory и выберите язык оригинала. Для Google доступно автоопределение.
3. Нажмите «Перекласти та зберегти» и выберите путь нового PDF.
4. Следите за прогрессом; после завершения откройте результат кнопкой в окне.

Перевод работает в `QThread`, поэтому окно остается отзывчивым.
Отмена проверяется между запросами. Текущего ответа переводчика нужно дождаться:
`deep-translator` не предоставляет параметр тайм-аута для этих клиентов.
При зависшем соединении ожидание может быть долгим; гарантированного предела
в 60 секунд нет. Окно остается отзывчивым. При закрытии во время работы
приложение запрашивает отмену; закройте окно повторно после завершения запроса.
Сохранение атомарное: временный файл заменяет выбранный результат только
после успешного перевода. Оригинал не перезаписывается.

Ограничения MVP:

- Страницы без извлекаемого текста пропускаются при переводе. Остальные
  страницы обрабатываются; в конце окно показывает номера пропущенных.
  В выходном PDF на месте такой страницы будет пояснение, чтобы номера
  страниц оригинала сохранились. Изображение скана не копируется.
- Если текста нет во всем PDF, приложение показывает информационное
  сообщение о необходимости OCR, не отправляет запросы переводчику и не
  заменяет существующий результат. OCR пока отсутствует.
- PDF с паролем отклоняются с сообщением.
- Создается новая простая верстка A4. Картинки, таблицы и оформление
  оригинала не переносятся. Порядок извлечения текста из многоколоночных
  PDF может отличаться от визуального.
- Длинный текст переносится на дополнительные страницы. Метка в PDF
  показывает номер страницы оригинала.
- Текст отправляется в выбранный сервис. История документов и настройки
  не сохраняются приложением. Работа без интернета не поддерживается.

## Сборка desktop-приложения

В активированном окружении:

```bash
python -m PyInstaller --noconfirm --clean PDFUkrainian.spec
python scripts/package.py
```

Результаты:

| Система сборки | Приложение | Архив для передачи |
| --- | --- | --- |
| macOS | `dist/PDFUkrainian.app` | `dist/PDFUkrainian-Darwin-*.zip` |
| Windows | `dist/PDFUkrainian/PDFUkrainian.exe` | `dist/PDFUkrainian-Windows-*.zip` |
| Linux | `dist/PDFUkrainian/PDFUkrainian` | `dist/PDFUkrainian-Linux-*.zip` |

Для Windows/Linux передавайте **всю папку**, а не один исполняемый файл.
Python на компьютере получателя не нужен. Для перевода нужен интернет.
ZIP сохраняет права исполняемых файлов и символические ссылки macOS.

PyInstaller собирает под текущую ОС и архитектуру: Windows `.exe` собирают
на Windows, macOS `.app` — на Mac. На Linux нужны системные библиотеки Qt
и графическая сессия для обычного запуска. Для headless-тестов используется
`QT_QPA_PLATFORM=offscreen`.

macOS-сборка учебная, без Developer ID и notarization; Windows-сборка тоже
без сертификата подписи. Распространение через магазины, установщик и
автообновления в MVP не входят.

## Jenkins

`Jenkinsfile` запускає **дві збірки паралельно** через Declarative Matrix:

Репозиторій: `https://github.com/CobbiFantom/desktop-jenkins.git`.
Задача `desktop-pdf-translator` читає `Jenkinsfile` із гілки `main`.
Після першого запуску Jenkins перевіряє Git кожні дві хвилини й автоматично
збирає нові коміти. Публічний webhook для цього не потрібен.
Деталі агентів та автозапуску: [ci/README.md](ci/README.md).

```text
Jenkins controller у Docker на VPS
  ├── агент macos на Mac → тести → .app → перевірка запуску → ZIP → Artifacts
  └── агент linux на VPS → тести → Linux-застосунок → перевірка запуску → ZIP → Artifacts
```

`agent none` означає, що controller лише керує запуском. Linux-агент можна
розмістити на тому ж VPS окремим процесом або контейнером. Наявність контейнера
Jenkins сама по собі не створює агент `linux`.

Налаштування перед першим запуском:

1. Додайте проєкт у Git. Створіть у Jenkins задачу **Pipeline from SCM**,
   вкажіть репозиторій і шлях `Jenkinsfile`. Потрібні плагіни Pipeline
   (з підтримкою Declarative Matrix), Git, JUnit та Timestamper.
2. У **Manage Jenkins → Nodes** додайте два агенти з мітками `macos` та `linux`.
   На кожному потрібні сумісна з вашим Jenkins Java, Git та Python 3.10–3.13.
   Обидва агенти мають бути online для одночасної роботи. Рекомендований
   початковий Number of executors — 1 на агенті, 0 на controller.
3. Для Mac задайте окремий Remote root directory, наприклад
   `/Users/cobbi/jenkins-agent`, а не папку розробки цього проєкту.
   Для Linux — окрему папку, доступну користувачу агента, наприклад
   `/home/jenkins/agent`.
4. На Linux потрібні модуль `venv`, `binutils`, системні бібліотеки Qt
   (зокрема OpenGL/EGL, D-Bus, xkbcommon, fontconfig) і шрифти з кирилицею.
   Якщо агент у контейнері, встановлюйте їх саме в образ агента.
5. У **Build with Parameters** перевірте `MACOS_PYTHON` (типово
   `/opt/homebrew/bin/python3.13`) та `LINUX_PYTHON` (типово `python3`).
   Значення — виконуваний файл Python, без додаткових аргументів.
6. Запустіть build. Кожен агент виконає Checkout → Install → Test →
   Build desktop → Smoke test, package and archive.

Кожна гілка працює у власній папці `ci-macos` або `ci-linux` усередині
Jenkins workspace. Перед checkout очищується лише ця папка. Свіжі venv,
звіти та пакети не використовуються повторно з минулого запуску.
JUnit-звіти мають назви й префікси тестів за платформою.
`QT_QPA_PLATFORM=offscreen` дозволяє тестувати Qt без монітора.

Гілки не зупиняють одна одну при помилці. Успішна гілка одразу архівує свій
ZIP, навіть якщо інша завершилася помилкою. Загальний статус такого build
буде невдалим; пакет успішної платформи залишиться доступним.
Загальний timeout — 45 хвилин, для кожної гілки — 30 хвилин разом з
очікуванням агента. Зберігаються останні 10 запусків та їхні артефакти.

### Де завантажити пакети

У Jenkins відкрийте **задачу → номер запуску → Artifacts**:

```text
dist/PDFUkrainian-Darwin-arm64.zip       # для цього Mac
dist/PDFUkrainian-Linux-x86_64.zip       # приклад для VPS x86_64
```

Архітектура в назві Linux-пакета залежить від VPS; ARM64 матиме іншу назву.
Це ZIP з готовим застосунком; DMG, DEB і майстер встановлення поки не створюються.
Архівування копіює файли з агента у сховище артефактів Jenkins — тримати Mac
online для подальшого завантаження вже збереженого пакета не потрібно.

За стандартного локального сховища Jenkins у Docker фізичний шлях буде на
зразок `/var/jenkins_home/jobs/<job>/builds/<номер>/archive/dist/`.
Для folder/multibranch jobs шлях має додаткові вкладені папки `jobs/`.
На самому VPS він залежить від volume або bind mount контейнера. Подивитися
монтування можна командою (замініть `JENKINS_CONTAINER` на назву контейнера):

```bash
docker inspect JENKINS_CONTAINER --format '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'
```

Папка `/var/jenkins_home` має зберігатися у постійному volume/bind mount, щоб
результати залишалися після перевідтворення контейнера. Якщо налаштований
зовнішній Artifact Manager, фізичне сховище буде визначене ним.

Ключі перекладачів не потрібні: тести використовують підставні відповіді.
Для встановлення залежностей потрібен доступ до PyPI. Підключення агентів
та запуск у вашому Jenkins виконуються окремо від зміни файлів проєкту.

Довідка: [Jenkins Matrix](https://www.jenkins.io/doc/book/pipeline/syntax/#matrix),
[архівування артефактів](https://www.jenkins.io/doc/pipeline/steps/core/#archiveartifacts-archive-the-artifacts).

## Тесты

```bash
python -m pytest -q
```

Проверяются украинские символы в PDF, перенос длинного текста, сохранение
исходного документа, атомарная запись, отмена, обработка сетевых ошибок,
передача языков, разбор ответа, лимиты MyMemory, пропуск страниц без текста,
сохранение номеров страниц и работа фонового потока Qt.

Проверка старта упакованного приложения на macOS/Linux:

```bash
QT_QPA_PLATFORM=offscreen dist/PDFUkrainian/PDFUkrainian --smoke-test
```

Этот smoke test проверяет создание окна, запись и чтение PDF с украинскими
символами внутри собранного приложения, а также создание клиентов переводчиков
без сетевого запроса. Настоящий перевод проверяется отдельно с интернетом.

## Что изучать в коде

```text
main.py                 точка входа
pdf_uk/app.py           окно, сигналы, слоты, жизненный цикл QThread
pdf_uk/translation.py   обертки deep-translator и деление текста на части
pdf_uk/documents.py     извлечение текста, перевод, создание PDF
tests/                 тесты логики и интеграция без внешнего API
PDFUkrainian.spec       конфигурация PyInstaller
scripts/package.py     переносимый архив сборки
Jenkinsfile            CI pipeline
```

Разумный следующий шаг после запуска: пройти по `start_translation()` →
`TranslationWorker.run()` → `translate_pdf()` и увидеть, как сигналы
возвращают прогресс в главное окно. Затем можно добавить OCR или предпросмотр.

PyQt6 распространяется по GPLv3 или коммерческой лицензии; перед закрытым
распространением приложения нужно выбрать подходящую лицензию Qt/PyQt.
См. [официальную страницу PyQt](https://www.riverbankcomputing.com/software/pyqt/).
