# PDF Ukrainian — навчальний desktop-проєкт

Невеликий застосунок на **Python + PyQt6**, який витягує текст із PDF,
перекладає його українською через **MyMemory або Google Translate / deep-translator**
і зберігає новий PDF. Для перекладу потрібен інтернет; сервер, Docker та API-ключі
не потрібні. **PyInstaller** пакує застосунок разом із Python і Qt.
**Jenkins** запускає тести, збирає застосунок і зберігає ZIP-артефакти.

## Швидкий початок

Потрібен Python **3.10–3.13**. Перевірено на Python 3.13 та macOS ARM64.
У macOS системний `python3` може бути старішим: у такому разі використовуйте
`python3.13` замість `python3` у першій команді.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python main.py
```

У Windows PowerShell замість `source` виконайте `.venv\Scripts\Activate.ps1`.
Без активації можна викликати `.venv\Scripts\python.exe` безпосередньо.
`requirements.txt` містить лише залежності застосунку; lock-файл також
містить інструменти тестування та збирання із зафіксованими версіями.

Невеликий англійський PDF для ручної перевірки: [translation-test-en.pdf](samples/translation-test-en.pdf).
Це одна сторінка з текстом, який можна виділити; OCR не потрібен.

## Як працює переклад

Перекладач обирається у вікні застосунку. Автоматичного перемикання між сервісами
немає: текст надсилається лише обраному провайдеру.

За замовчуванням обрано **MyMemory**: справжній переклад короткого PDF українською
перевірено в цьому середовищі. Сервер і ключ не потрібні; мова оригіналу обирається
вручну — англійська або російська. Безкоштовний ліміт без ключа — **5000 символів
на день**. Залишок ліміту залежить від попередніх запитів із тієї самої IP-адреси.
Документи довші за 5000 символів відхиляються до надсилання тексту.
Це варіант для невеликих навчальних PDF.
[Ліміти MyMemory](https://mymemory.translated.net/doc/usagelimits.php).

**Google Translate** також доступний, з автоматичним визначенням мови. Під час
перевірки 31 жовтня 2026 року Google повернув HTTP 429 навіть на перший короткий
запит. Цю зовнішню відмову неможливо виправити зміною PDF або пакуванням PyInstaller.
За такої відповіді оберіть MyMemory та явно вкажіть мову оригіналу.

Мінімальний приклад Google Translate через `deep-translator`:

```python
from deep_translator import GoogleTranslator

text = GoogleTranslator(source="auto", target="uk").translate("Hello world!")
```

У застосунку текст для Google ділиться на частини до 1800 символів, для
MyMemory — до 500 байтів UTF-8: кириличні літери займають більше одного байта.
Перекладаються всі сторінки, а не лише перша.

Це не офіційний Google Cloud Translation API: Google може тимчасово обмежувати
запити, а зміни вебсторінки можуть потребувати оновлення бібліотеки. Застосунок
показує зрозумілу помилку та зберігає попередній файл результату, якщо переклад
не завершився.

Документація: [deep-translator](https://deep-translator.readthedocs.io/en/latest/usage.html).

## Як користуватися

1. Оберіть PDF, у якому можна виділити текст.
2. Залиште MyMemory та оберіть мову оригіналу. Для Google доступне автоматичне визначення.
3. Натисніть «Перекласти та зберегти» й оберіть шлях нового PDF.
4. Стежте за перебігом; після завершення відкрийте результат кнопкою у вікні.

Переклад працює в `QThread`, тому вікно залишається чутливим до дій користувача.
Скасування перевіряється між запитами. Поточної відповіді перекладача потрібно
дочекатися: `deep-translator` не надає параметра тайм-ауту для цих клієнтів.
Якщо з’єднання зависло, очікування може бути тривалим; гарантованої межі
у 60 секунд немає. Під час закриття вікна застосунок запитує скасування;
закрийте вікно повторно після завершення запиту.
Збереження атомарне: тимчасовий файл замінює обраний результат лише після
успішного перекладу. Оригінал не перезаписується.

Обмеження MVP:

- Сторінки без тексту, який можна витягти, пропускаються під час перекладу.
  Решта сторінок обробляється; наприкінці вікно показує номери пропущених.
  У вихідному PDF на місці такої сторінки буде пояснення, щоб зберегти номери
  сторінок оригіналу. Зображення скану не копіюється.
- Якщо тексту немає в усьому PDF, застосунок показує інформаційне повідомлення
  про потребу в OCR, не надсилає запитів перекладачу та не замінює наявний
  результат. OCR поки не реалізовано.
- PDF із паролем відхиляються з повідомленням.
- Створюється нова проста верстка A4. Зображення, таблиці та оформлення
  оригіналу не переносяться. Порядок витягування тексту з багатоколонкових
  PDF може відрізнятися від візуального.
- Довгий текст переноситься на додаткові сторінки. Позначка в PDF показує
  номер сторінки оригіналу.
- Текст надсилається в обраний сервіс. Історія документів і налаштування
  не зберігаються застосунком. Робота без інтернету не підтримується.

## Збирання desktop-застосунку

В активованому середовищі:

```bash
python -m PyInstaller --noconfirm --clean PDFUkrainian.spec
python scripts/package.py
```

Результати:

| Система збирання | Застосунок | Архів для передавання |
| --- | --- | --- |
| macOS | `dist/PDFUkrainian.app` | `dist/PDFUkrainian-Darwin-*.zip` |
| Windows | `dist/PDFUkrainian/PDFUkrainian.exe` | `dist/PDFUkrainian-Windows-*.zip` |
| Linux | `dist/PDFUkrainian/PDFUkrainian` | `dist/PDFUkrainian-Linux-*.zip` |

Для Windows/Linux передавайте **всю папку**, а не лише виконуваний файл.
Python на комп’ютері отримувача не потрібен. Для перекладу потрібен інтернет.
ZIP зберігає права виконуваних файлів і символічні посилання macOS.

PyInstaller збирає під поточну ОС та архітектуру: Windows `.exe` збирають
на Windows, macOS `.app` — на Mac. На Linux потрібні системні бібліотеки Qt
та графічна сесія для звичайного запуску. Для тестів без монітора використовується
`QT_QPA_PLATFORM=offscreen`.

Збірка macOS навчальна, без Developer ID і нотаризації; збірка Windows також
без сертифіката підпису. Поширення через магазини, інсталятор та автоматичні
оновлення до MVP не входять.

## Jenkins

`Jenkinsfile` запускає **дві збірки паралельно** через Declarative Matrix:

Репозиторій: `https://github.com/CobbiFantom/desktop-jenkins.git`.
Задача `desktop-pdf-translator` читає `Jenkinsfile` із гілки `main`.
Після першого запуску Jenkins перевіряє Git кожні дві хвилини й автоматично
збирає нові коміти. Публічний webhook для цього не потрібен.
Деталі агентів та автозапуску: [ci/README.md](ci/README.md).

```text
Jenkins controller у Docker на VPS
  ├── агент macos на Mac → тести → .app → перевірка запуску → ZIP → Artifacts
  └── агент linux на VPS → тести → Linux-застосунок → перевірка запуску → ZIP → Artifacts
```

`agent none` означає, що controller лише керує запуском. Linux-агент можна
розмістити на тому ж VPS окремим процесом або контейнером. Наявність контейнера
Jenkins сама по собі не створює агент `linux`.

Налаштування перед першим запуском:

1. Додайте проєкт у Git. Створіть у Jenkins задачу **Pipeline from SCM**,
   вкажіть репозиторій і шлях `Jenkinsfile`. Потрібні плагіни Pipeline
   (з підтримкою Declarative Matrix), Git, JUnit та Timestamper.
2. У **Manage Jenkins → Nodes** додайте два агенти з мітками `macos` та `linux`.
   На кожному потрібні сумісна з вашим Jenkins Java, Git та Python 3.10–3.13.
   Обидва агенти мають бути online для одночасної роботи. Рекомендований
   початковий Number of executors — 1 на агенті, 0 на controller.
3. Для Mac задайте окремий Remote root directory, наприклад
   `/Users/cobbi/jenkins-agent`, а не папку розробки цього проєкту.
   Для Linux — окрему папку, доступну користувачу агента, наприклад
   `/home/jenkins/agent`.
4. На Linux потрібні модуль `venv`, `binutils`, системні бібліотеки Qt
   (зокрема OpenGL/EGL, D-Bus, xkbcommon, fontconfig) і шрифти з кирилицею.
   Якщо агент у контейнері, встановлюйте їх саме в образ агента.
5. У **Build with Parameters** перевірте `MACOS_PYTHON` (типово
   `/opt/homebrew/bin/python3.13`) та `LINUX_PYTHON` (типово `python3`).
   Значення — виконуваний файл Python, без додаткових аргументів.
6. Запустіть build. Кожен агент виконає Checkout → Install → Test →
   Build desktop → Smoke test, package and archive.

Кожна гілка працює у власній папці `ci-macos` або `ci-linux` усередині
Jenkins workspace. Перед checkout очищується лише ця папка. Свіжі venv,
звіти та пакети не використовуються повторно з минулого запуску.
JUnit-звіти мають назви й префікси тестів за платформою.
`QT_QPA_PLATFORM=offscreen` дозволяє тестувати Qt без монітора.

Гілки не зупиняють одна одну при помилці. Успішна гілка одразу архівує свій
ZIP, навіть якщо інша завершилася помилкою. Загальний статус такого build
буде невдалим; пакет успішної платформи залишиться доступним.
Загальний timeout — 45 хвилин, для кожної гілки — 30 хвилин разом з
очікуванням агента. Зберігаються останні 10 запусків та їхні артефакти.

### Де завантажити пакети

У Jenkins відкрийте **задачу → номер запуску → Artifacts**:

```text
dist/PDFUkrainian-Darwin-arm64.zip       # для цього Mac
dist/PDFUkrainian-Linux-x86_64.zip       # приклад для VPS x86_64
```

Архітектура в назві Linux-пакета залежить від VPS; ARM64 матиме іншу назву.
Це ZIP з готовим застосунком; DMG, DEB і майстер встановлення поки не створюються.
Архівування копіює файли з агента у сховище артефактів Jenkins — тримати Mac
online для подальшого завантаження вже збереженого пакета не потрібно.

### Автоматична публікація в GitHub Releases

Для спільного доступу відкрийте [GitHub Releases](https://github.com/CobbiFantom/desktop-jenkins/releases).
Задача `desktop-pdf-releases` перевіряє опубліковані релізи кожні дві хвилини.
Достатньо створити тег потрібної версії та натиснути **Publish release** у GitHub:
Jenkins збере саме коміт цього тега на Mac і Linux, перевірить обидві збірки та
додасть два готові ZIP до релізу. Чернетки не обробляються. Автоматичні архіви
`Source code` залишаються архівами вихідного коду.

Публікація потребує успішних перевірок обох платформ і доступного Mac під час
збірки. Після завантаження ZIP можна скачувати з GitHub незалежно від Jenkins
або Mac. Повторний запуск продовжує неповне завантаження; наявні файли з іншим
походженням автоматично не перезаписуються. Налаштування токена та відновлення
після помилок описані в [ci/README.md](ci/README.md#автоматичні-релізи-github).

За стандартного локального сховища Jenkins у Docker фізичний шлях буде на
зразок `/var/jenkins_home/jobs/<job>/builds/<номер>/archive/dist/`.
Для folder/multibranch jobs шлях має додаткові вкладені папки `jobs/`.
На самому VPS він залежить від volume або bind mount контейнера. Подивитися
монтування можна командою (замініть `JENKINS_CONTAINER` на назву контейнера):

```bash
docker inspect JENKINS_CONTAINER --format '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'
```

Папка `/var/jenkins_home` має зберігатися у постійному volume/bind mount, щоб
результати залишалися після перевідтворення контейнера. Якщо налаштований
зовнішній Artifact Manager, фізичне сховище буде визначене ним.

Ключі перекладачів не потрібні: тести використовують підставні відповіді.
Для встановлення залежностей потрібен доступ до PyPI. Підключення агентів
та запуск у вашому Jenkins виконуються окремо від зміни файлів проєкту.

Довідка: [Jenkins Matrix](https://www.jenkins.io/doc/book/pipeline/syntax/#matrix),
[архівування артефактів](https://www.jenkins.io/doc/pipeline/steps/core/#archiveartifacts-archive-the-artifacts).

## Тести

```bash
python -m pytest -q
```

Перевіряються українські символи в PDF, перенесення довгого тексту, збереження
оригіналу документа, атомарний запис, скасування, обробка мережевих помилок,
передавання мов, розбір відповіді, ліміти MyMemory, пропуск сторінок без тексту,
збереження номерів сторінок і робота фонового потоку Qt. Тести публікації
перевіряють прив’язку до коміту, повторні завантаження, конфлікти файлів та
захист токена від потрапляння до журналу чи стороннього сервера.

Перевірка запуску упакованого застосунку на macOS/Linux:

```bash
QT_QPA_PLATFORM=offscreen dist/PDFUkrainian/PDFUkrainian --smoke-test
```

Ця перевірка створює вікно, записує та читає PDF з українськими символами
всередині зібраного застосунку, а також створює клієнти перекладачів без
мережевого запиту. Справжній переклад перевіряється окремо з інтернетом.

## Що вивчати в коді

```text
main.py                 точка входу
pdf_uk/app.py           вікно, сигнали, слоти, життєвий цикл QThread
pdf_uk/translation.py   обгортки deep-translator і поділ тексту на частини
pdf_uk/documents.py     витягування тексту, переклад, створення PDF
tests/                 тести логіки та інтеграції без зовнішнього API
PDFUkrainian.spec       конфігурація PyInstaller
scripts/package.py     переносний архів збірки
scripts/github_release.py  завантаження пакетів у GitHub Releases
Jenkinsfile            тести, збирання та публікація пакетів
Jenkinsfile.releases   пошук опублікованих релізів і запуск збірок
```

Наступний крок після запуску: пройдіть шлях `start_translation()` →
`TranslationWorker.run()` → `translate_pdf()` і подивіться, як сигнали
повертають перебіг виконання до головного вікна. Потім можна додати OCR або
попередній перегляд.

PyQt6 поширюється за GPLv3 або комерційною ліцензією; перед поширенням застосунку
із закритим кодом потрібно обрати відповідну ліцензію Qt/PyQt.
Див. [офіційну сторінку PyQt](https://www.riverbankcomputing.com/software/pyqt/).
